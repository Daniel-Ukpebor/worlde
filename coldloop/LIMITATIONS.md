# Known limitations

- Software prototype only. No hardware was built, instrumented, validated, or calibrated during this work.
- All machine and mixture parameters are assumptions. Ice’s Corner supplies the motivating observation, not measurement data or endorsement.
- Two uniform nodes omit spatial pan gradients, scraper geometry, fluid convection, ingredient transport, ice crystal kinetics, concentration-dependent freezing curves, humidity, frost, contact resistance evolution, compressor startup transients, refrigerant dynamics, and temperature-dependent capacity/COP.
- Linear mushy enthalpy is an interpretable approximation. Modeled frozen fraction does not validate ice fraction, texture, viscosity, cracking, brittleness, or rollability. The scraper removes a batch; no real rolling outcome is predicted.
- Chop/contact behavior is an uncalibrated explicit heuristic. Spreading geometrically changes contact area and effective thickness. No mechanical work or heat generated by chopping/scraping is modeled.
- Constant electrical standby and COP are assumptions. Electrical results are calculations inside this model, not actual machine utility measurements.
- Adaptive hysteresis is a bounded trend heuristic. It need not outperform conventional control. Both receive the same measurements and dwell limits; no controller receives future order information.
- Fault handling is an educational inhibit rule with automatic recovery, not a safety-certified design. Plausible bias or stale readings can be missed.
- Synthetic demand replaces prior batches at each new order; incomplete batches are removed with their energy accounted for. No customer queue, food quality, throughput acceptance, or operator service time is predicted.
- Recovery means first band return after departure, not settling. Completed recovery means can omit censored disturbances.
- Live timing is browser-dependent. Exact numerical comparisons should use experiment runners, not manually timed clicks.
- Replay restores the last reset’s seed/settings/schedule; it does not replay manually timed actions or subsequent edits.
- Logs retain 3601 rows; event history retains 160 events. Chart rendering downsamples above 900 points, which can visually obscure very brief transitions. CSV contains the full retained one-second log, not integration substeps.
- Perfect Roll trials and controller comparisons are held in component memory. Export before changing sections. Notebook data is local to browser/origin and can be lost if storage is cleared; export JSON backups. There is no sync, account, import, or editing saved conclusions UI.
- A notebook record captures final configuration and retained telemetry, not a complete replayable history of parameter edits. Use a fresh reset and fixed configuration for a reproducible recorded run.
- Browser tests were run in Chromium, including a 390 px mobile viewport. Other browsers and physical mobile devices were not tested.
- The selected checkout was a Wordle repository. An actual pre-existing ColdLoop repository was not available for inspection. Original files were preserved; the new application is under `coldloop/`.
